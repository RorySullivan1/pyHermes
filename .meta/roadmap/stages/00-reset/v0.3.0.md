# version: v0.3.0
status: in-progress

## Goals
- Roadmap epic 0.2: fix three reference reports as the acceptance fixtures for every stage,
  under `reference/` by the names `daily-note`, `research-report` and `product-brochure`.
  Per the owner's 2026-10-28 decision, all three start as repo stand-ins:
  `examples/daily-investment-note`, `examples/quarterly-review` and the `tri_fold_letter`
  fixture. The real daily note and product piece replace theirs before Gate 1.
- Measure today's cost from data to a sendable note as the speed baseline: the code an author
  writes, and the time to a built, rendered and checked artifact.

## Objectives / acceptance
- Each stand-in is marked as one in its spec, with "replace before Gate 1" as a stated condition.
- Each reference report has a named owner, a written spec (audience, cadence, sections,
  data inputs) and a build script that renders today, committed under `reference/`.
- The benchmark is a documented, repeatable procedure (`python -m qa.benchmark`) with today's
  numbers recorded beside it, so every later gate can re-run it. The author's wall-clock
  minutes, which no script can measure, have a named place for the owner to record.
- The three reports render in CI as part of the suite, each linted clean of errors.
