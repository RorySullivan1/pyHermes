## Decisions

- **Parse, never grep** — `html.parser` from stdlib, so the check adds no dependency. The
  repo's own precedent: a `grep` for `Contact Us` once matched inside a section-marker
  comment and gave a confident wrong answer.
- **Every rule carries a citation** in `SOURCES`, with a test asserting each rule that *can
  fire* has one. Most cite Microsoft's Outlook Classic troubleshooting doc (grounded via the
  Microsoft Learn MCP, not memory); the image rules cite the repo's own decisions.
- **`max-width` is deliberately NOT denied**, though it is the repo's headline Outlook fact.
  The templates pair it with a `width=` attribute on purpose (12 occurrences), so a blanket
  rule fires on *correct* code — and a noisy rule gets switched off, which is worse than no
  rule. `img-width-attr` covers what matters; a test pins the exemption.
- **`DEFERRED_RULES` over permanent warnings.** Three sourced findings the templates violate
  are filed (#78) and listed as deferred, not shipped-as-warnings. A test asserts each entry
  names #78 and is not also in `SOURCES`, so switching one on is gated on fixing the finding.
- **`size-budget` extends `_validate_size`, never reshapes it** — that method is a
  `@staticmethod` on purpose and its message text is asserted by existing tests.
- **A section marker must contain a letter.** The templates use `<!-- ══════ -->` as
  decorative rules; counted as sections, the heaviest "region" was a row of box-drawing
  characters. A breakdown that names nothing explains nothing.
- **mso conditional comments are not linted as standard HTML.** `HTMLParser` hands them over
  as comment text, which is the wanted behaviour: the block carries Outlook-only VML, so
  standard rules would fire on markup that is correct *because* it is non-standard.
  `no-external-css` still reads comment text — a hidden `@import` is just as external.

## Gotchas & dead ends

- **`lint_email()` on a tiny `size_limit_kb` raises before linting.** `Email.render()`
  enforces the same limit itself, so a size-budget test must render under the real config and
  apply `config_override` only around the **lint** call. The two checks are layered, not
  parallel.
- **`Config` rejects `size_limit_kb=2` with default `inline_image_limit_kb=48`** (cross-field
  rule: one image may not exceed the whole budget), and `size_warn_kb=0` (must be positive).
  A tiny-limit override has to lower `inline_image_limit_kb` too.
- **Measure the rendered gallery, not the templates.** A template loop turns one source line
  into many rendered occurrences — the 107 unitless `line-height`s are ~8 distinct values.
- Exploratory scan before choosing rules is what kept it green: `max-width` (12), unitless
  `line-height` (107), `rgba()` background (1/fixture), `url('')` (2 fixtures) were all found
  *before* any rule was written, which is what turned three of them into #78 instead of a red
  linter.
