# 2026-08-24 02:30 · gmail-adapter

**Goal:** Ship #69 — the Gmail send adapter, first consumer of `svc/delivery`.

## What happened
- **Settled the open design question myself: pyHermes does NOT own the OAuth token lifecycle.** `send_message(message, *, transport, ...)` takes an already-authorized transport satisfying a one-method `Protocol`. Consequences, all deliberate:
  - **Zero new dependencies** — not even an optional extra. The module imports nothing from Google; `GoogleApiTransport` is a duck-typed three-line shim over the `service.users().messages().send(...)` chain. A test parses the module's **AST** to enforce this.
  - **No credential touches the package** — acquisition/refresh/revocation stay with the caller.
  - **Tests need no mailbox, no network, no recorded HTTP fixtures.** A fake transport is a class with one method.
  - Chose this over owning the OAuth flow because it *preserves* that option (a flow can be layered on later) while the reverse would mean ripping out deps and token storage.
- Shipped alongside: `svc/delivery/retry.py` (`retry_with_backoff`, transport-neutral, `sleep` injected), `TransportError`, and `to_wire_bytes()` extracted so `save_eml()` and the adapter serialise through one path.
- 45 new tests (`tests/test_retry.py`, `tests/test_gmail.py`), **468 total**. Verified end-to-end from a clean wheel install: builder → delivery → gmail against a fake service, CRLF intact, `multipart/related` payload.

## Gotchas & dead ends
- **My "imports nothing from Google" test initially failed on my own docstring** — it grepped source text and matched the *usage example* showing `from googleapiclient.discovery import build`. Same class of error the repo already recorded for templates. Rewrote it to walk the AST for real `Import`/`ImportFrom` nodes. **The parse-don't-grep rule applies to source files too, not just HTML.**
- Retry classification defaults to **not** retrying an unrecognised failure. On a send path an unknown error may already have delivered; a blind retry risks a duplicate. Only 429/5xx and network interruptions retry.
- Gmail's `HttpError` exposes `resp.status` on older releases and `status_code` on newer ones — read both by duck-typing rather than importing the exception class.
