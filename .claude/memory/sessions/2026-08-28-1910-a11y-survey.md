**The method worth reusing: look for a rule applied consistently in one layer
of the codebase and nowhere else.** That is what surfaced #114:

| | tables | with `role` |
|---|---|---|
| `base.html` + the four regions | 14 | **14** |

Somebody applied `role="presentation"` to one layer and stopped. It is

survived nine epics.

## #114, as shipped

11 layout tables marked, `scope="col"` on the data table's headers, and a
`table-role` lint rule.

**The rule fires in both directions, and that is the design.** A check that
only demanded the presentational role would be satisfied by marking *every*
table — stripping the semantics from the one table a screen reader should
navigate. So an unmarked layout table is an error and a marked *data* table is
an error too.

Three implementation facts worth keeping:

- **`th` is the discriminator.** It separates the two kinds in this codebase
  exactly, and it is the same signal a screen reader uses.
- **The open tables are a stack, not a flag.** The gallery's one data table
  renders inside two layout tables; a flat flag would let its `th` mark both
  ancestors as data, and the whole document would pass while every layout
  table stayed unmarked. A test pins that nesting case.
- **It decides at the closing tag and reports the opening one**, because that
  is where a reader has to go.

## The golden diff, proved rather than eyeballed

280 lines moved. A script (the #106 pattern) strips the two added attributes
from each added line and asserts it equals the removed line — every one did.
**No `.txt` or `.assets.txt` golden moved**, which is the orthogonality claim
from #53 paying out: an HTML attribute cannot reach the text projection.

## One pre-existing test had to be narrowed, correctly

`test_max_width_is_deliberately_allowed` asserted `not lint_html(...)` on a
snippet that is *also* an unmarked layout table. Its actual claim is "the
max-width rule does not fire", so it now asserts that plus a clean pass on
properly-marked markup. Narrowing a test to its real claim is right; weakening
the new rule to keep the old assertion literally true would not have been.

inside the issues themselves: bare element names, double-escaped character
